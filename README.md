## 🧭 How I got here

I started as a Data Analyst on a FinTech product, elbow-deep in ML model output — funnel analysis, cohort analysis, tracing bad predictions back to whichever stage of the pipeline broke them. Somewhere in there I was already testing and validating releases; the title just hadn't caught up yet. When it did, the analytical habit came with it: I still debug SQL-first, and I still want to know *why*, not just *that*.

That curiosity is also why I keep ending up owning things nobody assigned me. Both flagship frameworks below — the ERP stress-test setup and the AI/LLM testing harness — started as me looking at a slow manual process and deciding to fix it, before either was ever a ticket.

## 🧠 AI, from both sides

I didn't pick up AI testing recently — it's where I started, back in the Data Analyst days: elbow-deep in ML output, A/B testing in-house models against rule engines and third-party OCR. Formal QA just gave that instinct a framework. These days it shows up as:

- Computing the correct answer to a prediction myself, first — then grading a model's output against it, instead of eyeballing whether it "looks right"
- Handing an LLM (Claude Code) a PRD, my own notes, and team context to draft test cases from the real codebase — reviewing every single one before I trust it
- Tracing a wrong prediction back to the exact stage that caused it — extraction, rule engine, or model
- Using Claude Code and GitHub Copilot daily, without letting them replace my own review
